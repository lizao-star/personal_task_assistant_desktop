# 豆包 Agent 轻量化方案（补充）

> 本文档说明如何用**飞书豆包工作 agent + 多维表格技能**替代原方案中需要自建机器人/服务器的部分，
> 实现「手机发消息 → AI 拆解 → 自动入库」的轻量化体验。
> 返回入口：[CLAUDE.md](../CLAUDE.md) ｜ 原方案：[设计总纲.md](设计总纲.md)、[路线图.md](路线图.md)

---

## 一、为什么用这个方案

原路线图 M5（飞书机器人）和 M3（AI 拆解）需要：

- 自建机器人长连接服务
- 自己接入 LLM（DeepSeek）做自然语言解析
- 自己实现指令解析、卡片回调、幂等

**飞书豆包 agent 自带大模型和多维表格技能**，可以直接替代上述工作，省下大量开发量。

### 核心思路

```
手机飞书聊天（给豆包 agent 发消息）
    │  "下周三相交机器学习论文，5000字，复现一篇论文实验"
    ▼
豆包 agent（内置大模型做 NLU + 拆解）
    │  调用「多维表格」技能写入
    ▼
飞书多维表格「个人任务助理」
    ├─ 任务表（主任务，含 AI拆解、检查清单字段）
    └─ 子任务表（拆解出的子任务，关联主任务）
```

**豆包 agent 负责**：听懂自然语言、拆解任务、生成结构化字段、调用多维表格技能写入。
**我们负责**：设计好系统提示词、字段映射规则，以及（可选）校验写入结果。

## 二、能替代原方案的哪些部分

| 原阶段              | 原方案内容                                           | 替代程度           | 说明                                                                     |
| ------------------- | ---------------------------------------------------- | ------------------ | ------------------------------------------------------------------------ |
| **M3** AI 拆解      | 客户端接 DeepSeek 做一句话建任务、拆解               | **手机端完全替代** | 豆包直接拆+写表；客户端 AI 拆解可降级为可选（或不做）                    |
| **M5** 飞书机器人   | 自建机器人长连接 + `/add` `/today` 等指令 + 卡片回调 | **完全替代**       | 豆包 agent 就是机器人，无需自建                                          |
| **M6** Linux 服务器 | 机器人 + 定时调度 + AI 编排                          | **大幅简化**       | 不再需要机器人模块；仅保留定时调度（凌晨选青蛙、截止升级提醒、复盘触发） |
| **M7** 复盘统计     | 服务端调用 AI 生成复盘                               | **部分替代**       | AI 复盘文本可让豆包生成；统计计算和自动触发仍需服务端                    |
| M2 客户端写回       | 客户端建/完成/延期任务                               | **不替代**         | PC 端操作仍需客户端写回                                                  |
| M4 娱乐监督         | 进程监控 + 浏览器扩展 + 番茄钟                       | **不替代**         | 纯本地能力，agent 做不了                                                 |
| M8 日历时间块       | 自动排布算法                                         | **不替代**         | 需要复杂计算，仍需服务端                                                 |

### 对 M6 的具体影响

原 M6 服务器职责：机器人长连接、定时调度、AI 编排、复盘生成。
采用豆包方案后，服务器只需保留：

- **定时调度**（APScheduler）：每日 08:00 推今日议程、截止前升级提醒、每日凌晨选青蛙、22:00 触发复盘。
- **统计服务**：完成率、延期 Top3、娱乐 vs 专注时长。

机器人对话、AI 拆解、AI 复盘文本生成全部交给豆包 agent。服务器从「全功能后端」降级为「定时调度器 + 统计计算器」，开发量和资源占用都大幅降低。

## 三、配置步骤

### 1. 创建豆包工作 agent

1. 在飞书中找到「豆包」应用，创建一个**工作 agent**（企业专属）。
2. 给 agent 起个名字，比如「任务助理」。

### 2. 添加「多维表格」技能

在 agent 的技能配置中，添加飞书官方的**多维表格技能**，并授权它访问「个人任务助理」这个多维表格。

### 3. 编写系统提示词

这是最关键的一步。提示词要让豆包：

- 理解自然语言中的任务信息
- 按既定字段结构写入多维表格
- 遵守学术诚信边界
- 不确定时主动询问，不瞎猜

提示词模板见下方第四节。

### 4. （可选）配置多维表格字段映射

如果豆包默认写入字段不准，可以在提示词中明确指定每个字段的含义和取值范围。

## 四、系统提示词模板（可直接使用）

```
你是「个人任务助理」，帮助我把自然语言描述的任务拆解并写入飞书多维表格。
只操作这张表：https://xxx.feishu.cn/base/<你的多维表格token>（把链接换成你自己的）
只新增/修改记录，不改表结构（字段/视图/公式）；需要新字段时先告诉我。

## 你的能力
- 理解我发来的任务描述，提取任务名、截止时间、优先级、类型、预计耗时等信息
- 把大任务拆解成有序的子任务
- 生成检查清单
- 调用「多维表格」技能，把主任务写入「任务表」，子任务写入「子任务表」并关联主任务

## 写入规则
- 主任务写入「任务表」，字段映射如下：
  - 任务名：一句话概括
  - 状态：默认「待办」；如果是随手记的想法，写「收集箱」
  - 优先级：P0(当天/紧急) / P1(本周内) / P2(本月内) / P3(更远)；不确定写 P2
  - 任务类型：课程/科研/作业/考试/组会/生活/其他
  - 截止时间：从描述中提取；没提到就留空，不要瞎猜
  - 预计耗时：估算分钟数；不确定留空
  - 精力需求：高/中/低，根据任务难度判断
  - AI拆解：用 3-5 步描述完成这个任务的步骤
  - 检查清单：每行一项，列出完成前要确认的事项
  - 提醒规则：默认「提前1天,提前2小时,提前10分钟」
- 子任务写入「子任务表」，并通过「所属任务」关联到主任务
  - 子任务名：具体可执行的动作
  - 顺序：1, 2, 3...
  - 状态：默认「待办」
- 目标写入「目标项目表」，字段映射如下：
  - 目标名：一句话概括，例如「研一结束前完成小论文初稿」
  - 层级：年/季/月/周，不确定写「月」
  - 状态：默认「进行中」；尚未开始写「未开始」
  - 开始时间/结束时间：从描述中提取；没提到就留空，不要瞎猜
  - 描述：目标的具体说明
  - 关键结果：每行一条（OKR 思路）；不确定留空
  - 进度：系统自动计算，不要填
- 任务与目标关联：任务属于某个目标时，在「任务表」里填「所属目标」并选中该目标即可（双向关联会自动同步到目标表的「关联任务」，不要手动去改目标表这一列）

## 重要约束（必须遵守）
1. 学术诚信：你只做任务拆解、提纲、检查清单，绝不代写作业、论文或考试内容
2. 不确定就问：截止时间、优先级等关键信息不明确时，先问我再写入，不要编造
3. 写入后回复：用简洁的话告诉我「已创建：XXX，含 N 个子任务」，并列出子任务名
4. 如果描述太模糊（如「那个东西」），直接问我具体是什么，不要强行拆解
5. 只新增/修改记录，不改表结构（字段/视图/公式）；需要新字段时先告诉我，由我手动添加

## 示例
我：明天下午交高数作业，第三章习题1-10
你：已创建「高数作业 第三章习题1-10」，截止明天下午，优先级 P1，含 3 个子任务：
  1. 复习第三章知识点
  2. 完成习题 1-5
  3. 完成习题 6-10 并检查
```

## 五、与客户端的协同

豆包 agent 负责**手机端入库**，Windows 客户端负责**本地监督和提醒**，二者通过飞书多维表格天然同步：

| 场景                        | 入口                    | 实现方                     |
| --------------------------- | ----------------------- | -------------------------- |
| 手机随手记任务、拆解任务    | 飞书聊天给豆包发消息    | 豆包 agent（本方案）       |
| PC 端查看今日待办、监督娱乐 | Windows 客户端          | 现有 M1 客户端             |
| PC 端完成/延期任务          | Windows 客户端          | M2 客户端写回              |
| 番茄钟计时                  | Windows 客户端          | M4                         |
| 截止提醒、每日推送          | 飞书自动化 / 服务器调度 | 现有 M0 自动化 / M6 简化版 |

## 六、风险与对策

| 风险                               | 对策                                                                                     |
| ---------------------------------- | ---------------------------------------------------------------------------------------- |
| 豆包写入字段不准确（如优先级瞎填） | 提示词中明确字段取值范围；低置信度时让它写「收集箱」                                     |
| 子任务关联失败                     | 提示词中强调「先写主任务拿到 record_id，再写子任务并关联」；或先只写主任务，子任务后续补 |
| 豆包不遵守学术诚信                 | 提示词中用强约束表述，且可以在多维表格「AI拆解」字段后手动复核                           |
| 想撤销/修改写错的任务              | 直接在多维表格或客户端修改（客户端 M2 支持写回后更方便）                                 |
| 多维表格技能权限不足               | 确保 agent 已被添加为表格协作者，且多维表格技能已授权                                    |

## 七、验收标准

采用本方案后，以下体验应可达成：

- [ ] 手机飞书给豆包发「明天交高数作业第三章」，任务表出现一条记录，含正确的截止时间、优先级、子任务
- [ ] 描述模糊时（如「那个东西」），豆包主动询问而非瞎填
- [ ] 大任务（如「写课程论文」）被拆成多个子任务并关联到主任务
- [ ] 客户端同步后能看到豆包创建的任务
- [ ] 豆包不会代写作业内容，只输出拆解和检查清单
