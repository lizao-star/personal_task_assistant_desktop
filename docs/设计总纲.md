## 1. 定位与边界

**一句话定位**：「AI 帮我规划、拆解、提醒、监督、复盘」——不是「AI 帮我完成任务」。

| 能做                                                     | 不能做                                                       |
| -------------------------------------------------------- | ------------------------------------------------------------ |
| 任务拆解、生成下一步、排优先级、写检查清单、生成复盘报告 | 替你上课、揣摩老师真实意图、保证信息准确、代写论文、考试作弊 |

> **学术诚信红线（必须写入系统提示词）**：不代写、不代考、不提供可直接提交的成品作业；
> 只输出拆解、提纲、检查清单、自测问题。

### 原始需求（需求源头，保留备查）

1. 接入 AI，在每个任务上给出智能指导。
2. 开机自动启动，有任务时语音提醒（部分可提前提醒）。
3. 接入飞书（Windows 精美界面版 + Linux 服务器 24h 在线版），任务可从手机发入并双向同步。
4. 自动分类、排序、定优先级。
5. 监督执行：检测抖音/娱乐网站并持续提醒，直至关闭。
6. 常驻后台，资源占用低。

## 2. 方案收敛：为什么以飞书多维表格为中心

| 议题       | 早期方案（v2）                   | 最终方案（v3）                                                  |
| ---------- | -------------------------------- | --------------------------------------------------------------- |
| 中心数据源 | 自建 SQLite/FastAPI 为唯一事实源 | **飞书多维表格为唯一事实源（SSOT）**                            |
| 自建服务端 | 必需（M2 起）                    | **降级为可选**：只承担机器人长连接、事件订阅、定时提醒、AI 编排 |
| 同步方案   | 自研事件日志 + 乐观锁 + 冲突箱   | 用多维表格天然多端同步；客户端只做本地缓存 + 离线队列           |
| 表结构     | 9 张 SQLite 表                   | 6 张飞书多维表格                                                |
| 提醒       | 自建 APScheduler                 | MVP 用飞书自动化；后期升级为机器人卡片 + 服务器调度             |
| 微信       | 不建议                           | 不乱接个人微信，首选飞书                                        |

### 飞书多维表格的能力与限制（决定了架构必须这样设计）

**优势**：零服务器成本、手机/电脑/网页多端天然一致、手机可直接改任务、自带自动化与公式字段。

**限制与对策**

| 限制                                                   | 对策                                                             |
| ------------------------------------------------------ | ---------------------------------------------------------------- |
| API 有 QPS 限流，不能高频逐秒写入                      | 娱乐监控改为「会话结束聚合写一条」，不逐秒上报                   |
| 无内建变更 Webhook 推送到自建服务                      | MVP 用客户端定时轮询增量拉取（30~60 秒），后期用服务器做事件订阅 |
| 无乐观锁 / 版本号                                      | 用「最后更新时间」+ 本地 `last_sync` 游标；冲突以表格为准并提示  |
| 公式语法与 Excel 不同，且公式字段不能通过 API 任意写入 | 公式字段后期单独做；排序先用客户端规则计算                       |
| 单表行数建议控制在数万行内                             | 娱乐监控日志按月归档/清理                                        |

> **结论**：飞书多维表格适合当「任务与目标」的中心库，**不适合当高频日志库**。
> 因此娱乐监控明细只存本地，仅聚合结果写入日志表。

## 3. 系统架构

```
                        ┌─────────────────────────────────────────────┐
                        │      飞书多维表格「个人任务助理」＝ 唯一事实源    │
                        │  任务表 / 子任务表 / 目标项目表                  │
                        │  每日复盘表 / 娱乐监控日志表 / 设置表             │
                        └───┬──────────────┬──────────────┬────────────┘
                            │              │              │
        bitable OpenAPI     │              │              │  bitable OpenAPI
   ┌────────────────────────┘              │              └──────────────────────┐
   ▼                                       ▼                                    ▼
┌──────────────────────┐        ┌──────────────────────┐        ┌──────────────────────┐
│  Windows 客户端        │        │  飞书 App（手机/桌面）  │        │  Linux 服务端（可选后期）│
│  Python + PySide6     │        │  直接编辑表格          │        │  FastAPI + APScheduler │
│  ├─ 托盘 / 开机自启     │        │  机器人消息 + 卡片      │        │  ├─ 机器人长连接/事件订阅 │
│  ├─ 今日议程 / 看板     │        │  飞书自动化推送         │        │  ├─ 定时提醒与升级       │
│  ├─ 系统通知 + TTS     │        └──────────────────────┘        │  ├─ AI 编排（DeepSeek）  │
│  ├─ 前台窗口监控        │                                        │  └─ 复盘统计             │
│  ├─ 本地缓存 + 离线队列 │                                        └──────────────────────┘
│  └─ 本地 API(供扩展上报) │
└──────────┬───────────┘
           │ http://127.0.0.1
           ▼
┌──────────────────────┐
│  浏览器扩展 (MV3)      │
│  当前域名 + 时长统计    │
└──────────────────────┘
```

**三条数据流**

1. **任务流**：客户端 / 飞书 / 服务器三方读写同一张多维表格 → 天然同步。
2. **监督流**：扩展 + 客户端采集 → 本地聚合 → 会话结束写「娱乐监控日志表」。
3. **复盘流**：多表数据 → 服务器/客户端统计 → 写「每日复盘表」。

**Windows 客户端与服务器分工**

- Windows 客户端：**本地交互与监督**（提醒、语音、窗口监控）。
- Linux 服务端：**无人值守能力**（关机也能收飞书提醒、机器人对话、AI 拆解）。
- 二者不互相同步，**都写在飞书多维表格上**，因此不存在双写冲突。

## 4. 数据模型（飞书多维表格）

6 张表的**完整字段定义、视图、飞书自动化配置**见 [飞书表结构.md](飞书表结构.md)。
本节只记录**架构层面的关键规则**。

### 4.0 三层任务体系（时间尺度 + 投入方式双重判定）

三层表不是平行的存储，而是「长期方向 → 中期任务 → 当日动作」的分解链：

| 层级         | 表         | 时间尺度         | 判断标准                                      | 例子                      |
| ------------ | ---------- | ---------------- | --------------------------------------------- | ------------------------- |
| L1 目标/项目 | 目标项目表 | **≥ 30 天**      | 距截止 ≥30 天 **且** 需持续投入、可分阶段推进 | 研一结束前完成小论文初稿  |
| L2 任务      | 任务表     | **1 天 ~ 30 天** | 可安排进日程、几天到几周完成                  | 写完文献综述第二章        |
| L3 子任务    | 子任务表   | **1 天内**       | 一次坐下就能完成的具体动作                    | 精读 3 篇核心文献并做笔记 |

> **时间跨度只是必要条件，不是充分条件**。远期但一次性办完的事（开会、体检、报到、面试、领材料）
> 即使截止在 3 个月后，也判 L2 任务——它不需要持续投入，拆不出有意义的阶段。
> 只有「时间跨度够长 + 需要持续投入」同时成立，才是 L1 目标/项目。

**规则**：

- 每个任务最多挂 1 个「所属目标」（任务表关联字段）；目标 → 任务 → 子任务 全靠关联字段串联，不复制内容。
- **AI 建任务先判层级再落表**：一句话输入 → AI 判定 L1/L2/L3 → L1 自动向下拆成若干 L2 任务（挂所属目标），L2 可再拆 L3 子任务，一次写多张表；判定结果与拆解草稿在对话框里展示，用户可改层级、增删任务后再确认入库（AI 只建议，规则与用户做决策）。
- **层级由规则引擎复核**（`parser.py`，纯函数可复现）：
  - goal 无截止时间 → 降级 task；
  - goal 距截止 < 30 天 → 降级 task；
  - goal 命中一次性事件词（会议/体检/报到/面试/领取/办理…，且不含准备/筹备/备考/复习/组织等投入词）→ 降级 task；
  - 反之，模型判 task，但「≥30 天 + 非一次性 + 含持续投入信号（备考/论文/项目/考试…）」时，追加一次按目标拆解的追问；模型仍坚持 task 则尊重原判定。
  - 所有降级/升级都写入 `level_note`，并在对话框提示用户确认；模型自评的 `level_confidence` 低于 0.6 时额外提示「层级可能判错」。
- **L1 必须向下拆解**：目标是阶段性方向，落表时必须带 ≥2 个 L2 任务；AI 拆不出足够的任务说明层级判定不成立，**降级为 L2 任务并压到低置信度进收集箱**，由用户人工确认，不允许出现「光杆目标」。
- **目标级输出要区分三件事**：`advice`（怎么做好：重点、方法、取舍）、`tasks`/`subtasks`（要做什么：需投入时间的步骤）、`checklist`（一次性核对项）。报名截止、打印准考证这类中间时间节点不单独设结构，直接落成带截止时间的任务（任务级则作为一条子任务）。
- **L2 按需拆 L3**：普通任务只在确实跨步骤时才拆子任务，且 `subtask_needed=false` 时强制清空（宁缺勿碎，禁止把「打开文档」这类一次性动作拆成子任务）。
- **L3 不再向下拆**：`level=subtask` 时清空 `tasks`/`subtasks`，直接落到子任务表。
- 判定不了的（描述模糊、置信度低）一律降级为 L2 任务进收集箱，绝不硬猜层级。
- 目标项目表同一时间保持少量（建议 ≤ 5 个活跃目标），防止目标通胀。

> M4.5 已实现：AI 解析/校验在 `app/ai/parser.py`，目标读写与关联在 `app/feishu/repository.py`，
> `goal_create` 离线队列 op 在 `app/services/sync.py`，主窗口「🎯 目标计划」区在 `app/ui/main_window.py`。

### 4.1 约定

- 所有字段读写统一用**字段名**（比 field_id 易读），代码中集中常量化（`app/constants.py`）。

## 5. 模块设计

### 5.1 优先级引擎（规则优先，AI 只建议）

```
urgency       = f(截止时间)      # 越近越大
blocking      = g(依赖关系)      # 阻塞下游越多越大
energy_match  = h(当前时段 vs 精力需求)
penalty       = 延期次数 * 0.02

priority_score = 0.40*urgency + 0.30*重要性 + 0.20*blocking + 0.10*energy_match - penalty
```

- urgency 分档：已逾期 1.00 / 24h 内 0.95 / 3 天内 0.70 / 7 天内 0.50 / 更远 0.30。
- **客户端本地计算**（不依赖飞书公式字段）。
- 每日自动挑选 3 个最高分且未完成的任务标记为「青蛙」。
- AI 只输出建议文本，用户一键采纳。
- 实现：[priority.py](../client_windows/app/services/priority.py)（纯函数 + 单元测试）。

### 5.2 提醒体系（两层）

- **第一层 · 飞书自动化（已落地）**：08:00 推今日任务；22:00 推未完成；截止前 1 天 / 2 小时 / 10 分钟提醒；P0 进行中监督提醒。
- **第二层 · 客户端/服务器增强**：本地系统通知 + TTS 语音（离线可用）；服务器做升级提醒（错过 → 30 分钟后升级 → 最多 3 次）；勿扰时段（默认 23:00–07:00）静默；上课/会议时间块内不弹窗。
- 用「提醒状态」字段 / 本地 `reminder_log` 去重；`完成时间` 一填即停止提醒。

### 5.3 监督 / 专注模块

**检测来源**

- Windows：`psutil` 枚举进程 + `pywin32` 取前台窗口标题/进程名（识别 douyin.exe 等）。
- 浏览器：扩展读当前域名，上报 `http://127.0.0.1:PORT`（**不过服务器**，隐私优先）。
- 只记录域名/进程名与时长，**不记录页面内容**。

**四级升级（阈值从设置表读，可配）**

| 级别 | 触发           | 动作                             |
| ---- | -------------- | -------------------------------- |
| L1   | 连续 > 10 分钟 | 系统通知「该回去学习了」         |
| L2   | > 20 分钟      | TTS 语音提醒                     |
| L3   | > 30 分钟      | 飞书推送卡片（含「已关闭」按钮） |
| L4   | > 45 分钟      | 全屏遮罩，需手动确认关闭         |

**豁免**：白名单进程/域名、每日豁免次数、番茄钟休息期、标记为娱乐的时间块。
**番茄钟**：默认 25/5，可绑定任务，自动累计「实际耗时」。

### 5.4 AI 编排层（DeepSeek 为主，手机端可由豆包替代）

> **轻量化方案**：手机端的任务解析与拆解可由飞书豆包工作 agent 直接完成（见 [豆包agent轻量化方案.md](豆包agent轻量化方案.md)），无需自建 AI 服务。本节为客户端/服务端自建 AI 的设计，手机端可跳过。

**三类调用场景**（其他一律走规则，控成本）：解析（自然语言 → 结构化数据，**含 L1/L2/L3 层级判断与向下拆解**，见 4.0）、拆解（大任务/目标 → 子任务 + 检查清单 + 下一步）、复盘（数据 → 复盘报告）。

**统一输出契约（JSON Schema 强约束）**

```json
{
  "level": "task",
  "title": "读完《XXX》并写 500 字笔记",
  "status": "收集箱",
  "priority": "P1",
  "task_type": "科研",
  "importance": 4,
  "energy": "高",
  "estimate_min": 120,
  "due_at": "2026-10-10T23:59:00+08:00",
  "tags": ["论文", "阅读"],
  "subtasks": ["下载 PDF", "精读方法部分", "写 500 字笔记"],
  "checklist": ["记录 3 个创新点", "标注可复现代码"],
  "confidence": 0.82
}
```

**层级字段与拆解契约（三层打通的核心）**

- `level`：`goal | task | subtask`，AI 按**时间跨度 + 是否需持续投入**双条件判断（L1 目标：距截止 ≥30 天且可分阶段推进 / L2 任务：1~30 天 / L3 子任务：<1 天），判不准填 `task` 降级进收集箱。远期一次性事件（会议/体检/报到）仍填 `task`。
- `level_confidence`：层级自评置信度（0~1），与整体 `confidence` 独立；`< 0.6` 时 UI 提示用户确认层级。
- `advice`：策略建议（怎么做好），与 `subtasks`（做什么）分离。中间时间节点（报名截止、打印准考证）不单独设字段，直接写成带截止时间的 L2 任务或一条子任务。
- `level = "goal"` 时额外输出 `tasks` 数组，把目标向下拆成 L2 任务，每个任务可再带 `subtasks`（L3）：

```json
{
  "level": "goal",
  "level_confidence": 0.82,
  "title": "通过 2026 年 12 月六级笔试并取得 500+",
  "advice": "重点是听力和阅读，占分七成；每天固定 1 小时真题精练。",
  "tasks": [
    { "title": "打印笔试准考证", "due_at": "2026-12-01T09:00:00+08:00", "subtasks": [] },
    { "title": "完成近 5 年真题精练", "due_at": "2026-12-10T23:59:00+08:00",
      "subtasks": ["听力真题 10 套", "阅读真题 10 套"] },
    { "title": "写作与翻译模板训练", "due_at": "2026-12-08T23:59:00+08:00", "subtasks": [] }
  ],
  "confidence": 0.78
}
```

**规则**：`confidence < 阈值(0.6)` → 写入「收集箱」并标注待确认，不猜；失败重试 1 次，仍失败则退化为「只取标题」；供应商抽象为 `LLMProvider` 接口，DeepSeek 主用，通义/智谱可切换；Key 只放本地配置/环境变量。
**拆解校验**（M4.5 已实现，见 `app/ai/parser.py`）：goal 三条降级（无 deadline / <30 天 / 一次性事件）→ 转 `task` 并记 `level_note`；`level=goal` 但 `tasks` < 2 → 降级为 `task`、清空 `tasks`、`confidence` 压到 ≤ 0.4 进收集箱；疑似目标追加一次按目标拆解的追问；`level=subtask` → 清空 `tasks`/`subtasks`；`subtask_needed=false` → 清空 `subtasks`；`checklist` 与 `subtasks` 重复项去重；`tasks` 最多 5 个、每个任务的 `subtasks` 最多 6 条。
**落表顺序**（goal 级）：先写目标项目表拿到 record_id → 再写任务表并在「所属目标」关联字段带上它 → 最后写子任务表并关联所属任务；中途任一步失败已写入的部分保留，失败部分走离线队列重试（`goal_create` op，目标与任务均按「外部ID」幂等，重推只补未完成部分）。

### 5.5 飞书机器人（后期，可由豆包 agent 替代）

> **轻量化方案**：本节的自建机器人可完全由**飞书豆包工作 agent + 多维表格技能**替代，无需自建长连接服务。详见 [豆包agent轻量化方案.md](豆包agent轻量化方案.md)。以下指令设计同样适用于豆包 agent 的系统提示词。

**指令**

```
/today              今日议程与三只青蛙
/add 明天下午交高数作业   自然语言建任务
/done 3            完成列表第 3 项
/defer 3 1d        延期 1 天
/review            生成本周复盘
/focus 25 写论文     启动 25 分钟番茄钟
```

**卡片按钮**：`完成 / 延后1天 / 改到今晚 / 设为今天青蛙`。同一消息重复回调需用 message_id 幂等。

### 5.6 Windows 客户端

**功能**：托盘常驻 + 开机自启、今日议程/看板/收集箱、系统通知 + TTS、前台窗口监控、番茄钟、本地缓存与离线队列、供扩展上报的本地 API。
**资源目标**：常驻内存 < 150 MB，空闲 CPU < 1%；监控采样 5 秒一次。

### 5.7 同步与冲突

- **飞书多维表格 = 唯一事实源**，所有端只读写它，无需自研同步协议。
- 客户端维护本地 SQLite 缓存 + `last_sync` 时间戳，按「最后更新时间 > last_sync」增量拉取。
- 离线变更进本地队列，恢复后按序写入；用 `外部ID` 保证幂等。
- 冲突：多维表格无版本号 → 以表格当前值为准，客户端未推送的改动进「冲突提示」。
- 轮询频率 30~60 秒（默认 45），避免触发限流。

### 5.8 安全、隐私、备份

- App ID / App Secret / DeepSeek Key 只放环境变量或本地配置文件，**不入库、不上传、不进 git**。
- 客户端只申请必要权限：多维表格读写、发消息。
- 娱乐监控明细只在本地，仅聚合结果写飞书。
- 多维表格自带历史版本与回收站作为天然备份；客户端再导出周备份 JSON。
- AI 输入最小化：只传任务名、截止时间等必要字段，敏感内容脱敏。

## 6. 技术选型

| 层             | 选型                                                                 | 理由                                             |
| -------------- | -------------------------------------------------------------------- | ------------------------------------------------ |
| 中心数据源     | **飞书多维表格**                                                     | 零成本多端同步，手机可编辑，已落地               |
| Windows 客户端 | **Python 3.11 + PySide6**                                            | 与脚本/AI 同语言，托盘/通知/监控库齐全，占用可控 |
| 飞书接入       | `requests` 直连 OpenAPI（当前）；官方 `lark-oapi` 可选               | 依赖少、可控                                     |
| AI             | **DeepSeek**（通义/智谱可切换）                                      | 便宜、中文强、支持 JSON 输出                     |
| 手机端 AI 入库 | **飞书豆包工作 agent + 多维表格技能**（轻量化，替代 M3 手机端 + M5） | 零开发，自带大模型，直接写表                     |
| 定时/自动化    | MVP：飞书自动化；后期：APScheduler                                   | 先零代码，再自研                                 |
| 通知/语音      | `winotify` + `pyttsx3`（当前）/ Edge-TTS（后期）                     | 系统通知 + 中文语音                              |
| 窗口监控       | `psutil` + `pywin32`                                                 | 前台进程/窗口检测                                |
| 本地存储       | SQLite（仅缓存 + 离线队列）                                          | 不是中心库                                       |
| 浏览器扩展     | Chrome/Edge MV3                                                      | 域名与时长统计                                   |
| 服务器（可选） | Linux 1C1G + FastAPI + Docker                                        | 只做机器人与调度                                 |

## 7. 风险与对策

| 风险               | 影响          | 对策                                            |
| ------------------ | ------------- | ----------------------------------------------- |
| 飞书 API 限流      | 同步失败/被限 | 45 秒轮询、批量接口、指数退避、只拉增量         |
| 多维表格无版本号   | 并发覆盖      | 以表格为准 + `外部ID` 幂等 + 本地改动提示       |
| 高频写日志撑爆表格 | 表膨胀        | 会话聚合写入、按月归档                          |
| AI 幻觉/超时/断网  | 任务解析错    | 强 JSON 契约 + 重试 + 规则兜底 + 低置信度转人工 |
| 提醒过频被反感     | 弃用          | 默认仅作业/考试开语音；勿扰 + 豁免 + 升级上限   |
| 表格结构被误改     | 客户端崩      | 启动自检字段完整性，缺失字段报警并降级          |
| 凭证泄露           | 数据/费用损失 | Key 只在本机环境变量，不入库不上传不提交 git    |
| 项目变待办垃圾场   | 失去价值      | 强制日/周复盘 + 完成率与延期统计                |
| 后台占用过高       | 体验差        | 采样监控、PySide6 轻客户端、AI 走云端           |
