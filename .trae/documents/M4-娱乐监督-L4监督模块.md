# M4 娱乐监督（L4）实现方案

## Context

M0-M3 已完成，飞书表/客户端读写/AI 拆解链路跑通。本期落地 M4 路线图中的「娱乐监督」一环，强度 L4：检测抖音/娱乐网站，按 L1→L2→L3→L4 四级升级（10/20/30/45 分钟），L4 触发时二选一执行用户配置的动作——**全屏遮挡** 或 **强制关闭对应网页**。番茄钟推到后续阶段不做。

设计目标：纯规则驱动（无 AI），5 秒采样，会话结束聚合写一条飞书「娱乐监控日志表」记录，不逐秒上报。复用现有 Notifier/LocalCache/SyncWorker/FeishuClient，遵循「飞书 SSOT、密钥不入库、字段常量化、纯函数配单测、网络只在后台线程」项目硬规则。

## 核心模块设计

### monitor.py（监控引擎）
`MonitorWorker(QObject)` moveToThread 独立 QThread。5 秒 QTimer 触发 `_sample()`：
1. `pywin32.GetForegroundWindow` + `GetWindowText` 取前台窗口标题与进程名（`psutil.Process(pid).name()`）；
2. 向 `LocalApiServer` 取最近 5 秒扩展上报的 `{domain,title,seconds}`（无扩展则空）；
3. 调 `monitor_rules.is_exempt(title, domain, whitelist)` 判断豁免；
4. 命中娱乐域且非豁免 → 维护会话：`cache.start_session` 首次，`update_session` 续期；
5. 调 `monitor_rules.evaluate(state, elapsed_s, cfg)` 决定本帧动作；
6. 通过 Qt 信号分发到主线程（**绝不在工作线程操作 UI 或网络**）：
   - `notify_requested(level, text)` → `Notifier.notify`+`speak`（L1/L2/L3）
   - `action_requested(kind)` → `Overlay.show()` 或 `KillTab.close_tab(domain)`（L4，按 `l4_action` 配置）
   - `session_ended(aggregate)` → `cache.end_session` + `enqueue_monitor_log` → 触发增量同步
7. 切走前台或进入豁免 → `monitor_rules.aggregate_session` 收尾。

### monitor_rules.py（纯函数）
- `is_exempt(title, domain, whitelist_titles, whitelist_domains) -> bool`
- `pick_level(elapsed_s, thresholds) -> int`（0=无,1-4=L1-L4）
- `next_action(cur_level, new_level, fired_count) -> str`（`"none"/"notify"/"escalate"/"finish"`）
- `aggregate_session(samples) -> dict`（取最长 domain/title、求和 seconds、是否提醒/关闭/备注）

### overlay.py
`Overlay(QWidget)` 全屏 `WindowStaysOnTopHint|FramelessWindowHint`，半透明红底，居中文案「已连续娱乐 XX 分钟，请回到学习」+ 「我已收到，关闭」按钮；点击发 `closed()` 信号回 `MonitorWorker` 标记会话 `closed=True`。

### kill_tab.py
`close_tab(domain, title)` 双路径：
1. POST `http://127.0.0.1:8765/close-tab` `{domain}`，3 秒内扩展回 `{ok:true}` 则结束；
2. 超时降级 `pywin32.EnumWindows` + `GetWindowText`，按窗口标题含 domain 关键词 `PostMessage(WM_CLOSE)`，只关匹配窗口不杀进程。

### local_api.py
`LocalApiServer(ThreadingHTTPServer)` 监听 127.0.0.1:8765：
- `POST /report` `{domain,title,seconds}` → 写入内存最近样本缓存（MonitorWorker 取走即清）
- `POST /close-tab` `{domain}` → 转发到扩展（background.js 接收）
- `GET /health` → 扩展探测存活
- 仅本机回环，无鉴权

### extension/（MV3）
- `manifest.json`：matches `["<all_urls>"]`，permissions `["tabs","scripting","storage"]`，host `http://127.0.0.1:8765/*`
- `content.js`：每 5 秒 `fetch('/report', {method:POST, body: {domain,title,seconds}})`
- `background.js`：service worker 监听 `/close-tab`（通过 `chrome.runtime.onMessage` 来自 content），调 `chrome.tabs.query({url:"*://domain/*"})` + `chrome.tabs.remove`

## 数据流

前台窗口采样 → 命中娱乐域 → `cache.start_session` → 每 5 秒 `evaluate()`：达 L1/L2/L3 触发 `Notifier`（通知+语音），`fired_count+1`；达 L4 触发 `action_requested`（按 `l4_action` 配置走 Overlay 或 KillTab），置 escalating；窗口切走/豁免 → `aggregate_session` → `cache.end_session` + `enqueue_monitor_log` → `SyncWorker.push_monitor_logs` 调 `create_monitor_log` 写入飞书「娱乐监控日志表」，成功删行。一次会话仅一条聚合记录，断网时留 `pending_monitor_logs` 下次同步补推。

## 配置 schema

`config/settings.yaml` 增段：
```yaml
monitor:
  enabled: true
  sample_interval_seconds: 5
  whitelist_domains: ["feishu.cn", "github.com", "cnki.net"]
  whitelist_titles: ["Word", "PyCharm", "Visual Studio"]
  escalation:
    l1_minutes: 10
    l2_minutes: 20
    l3_minutes: 30
    l4_minutes: 45
  l4_action: "overlay"   # overlay | kill_tab
  pause_with_reminder: true   # 暂停提醒期间也暂停监督
```

`config/.env` 增 `FEISHU_MONITOR_LOG_TABLE_ID=tblxxxx`（飞书「娱乐监控日志表」table_id，不填则仅本地缓存不入库）。

## 验收路径

1. **白名单豁免**：在 PyCharm 操作 60 秒，应一直 idle，无通知。
2. **四级升级**：打开 bilibili.com 标签保持前台，10 分钟系统通知、20 分钟语音、30 分钟再次通知/卡片，45 分钟触发 L4 动作。
3. **L4 overlay**：`l4_action=overlay` 时全屏遮罩弹出，点按钮后遮罩消失，会话 `closed=True`。
4. **L4 kill_tab（扩展在线）**：装 MV3 扩展，`/health` 返回 200，45 分钟匹配标签被 `chrome.tabs.remove` 关闭。
5. **L4 kill_tab（扩展离线降级）**：禁用扩展，45 分钟走 Win32 关匹配窗口（标题含 domain）。
6. **聚合写表**：会话结束 `pending_monitor_logs` 增一条；触发同步后飞书「娱乐监控日志表」增一行，字段：时间=会话结束时刻、进程名=chrome、窗口标题=最长停留标题、URL=最长 domain、持续时长=总秒数、是否提醒=true、提醒次数=3、是否关闭=true、备注="L4 触发"。
7. **暂停豁免**：托盘勾「暂停提醒」期间监督不触发任何动作（`pause_with_reminder`）。
8. **断网**：会话结束飞书不可达，记录留 `pending_monitor_logs`，下次同步补推。
9. **资源**：常驻内存 < 150 MB，空闲 CPU < 1%。
10. **单测**：`python -m unittest discover -s tests -v` 全绿，新增 `test_monitor_rules.py` 覆盖阈值/状态机/聚合纯函数。
